## Verdict

**Approve with changes.** The architecture holds up:

- a category-neutral `transactions` parent;
- one typed fact table with a single writer;
- pure, fixture-tested evaluators in versioned files;
- opportunity identity kept separate from cases;
- claims widened instead of a second case table;
- the existing ledger reused;
- httpAction-only uploads.

None of these needs to be replaced. **The findings are 0 critical, 11 high, 14 medium and 11 low.** Every high finding is a specification defect that implementers would build exactly as written. The main effects:

- the wave-1 R01 parity gate cannot pass;
- the same money is counted twice across dashboard tiles;
- "I don't know" resolves as a known fact;
- a carrier's lateness shows as the user's expired path;
- informal email looks like a filed billing-error notice;
- a real mailing cannot be recorded;
- a published retention promise silently becomes false;
- card statements can reach the model;
- no one is assigned to activate or refresh a rule pack.

Most fixes are a few lines of contract text plus a named regression test. The list of changes required before each wave is at the end.

## Attacks tried that hold (one line each)

- **Concurrent `putFact` supersede:** both writers read the cell's index range; OCC serializes them and the loser retries onto the winner's row. Holds.
- **A stale extracted candidate overriding a user confirmation:** step 1 precedes step 4, and a candidate supersedes nothing. Holds. (DA-A-1 is the `user_unknown` special case.)
- **Subject keys forged across transactions:** `putFact` checks `item.purchaseId` and `incident.transactionId`; ordinal subjects are scoped to their transaction. Holds.
- **Concurrent `openCase` and R01 auto-open (O1):** both read `activeClaimId` and the item range; OCC retries return the existing claim. Holds. convex-test cannot exercise real concurrency, so this rests on read-set semantics.
- **A rule-version bump creating a second opportunity:** `dedupeKey` excludes `ruleVersion`. Holds, provided `remedyKey` and `subjectKey` stay stable across versions — add a test.
- **Audit of which rule version produced an approved packet:** `binding.evaluationId` points to the rule id/version plus the fact ids in `conditions`. Holds for stored facts; legacy-adapter cells need their values stored (DA-A-15).
- **The lazy `ensurePurchaseTransaction` race:** the `by_purchase` equality read serializes it. Holds.
- **Wave-2 deploy order:** widened validators accept every stored document, and the old frontend already handles `item: null`. Holds. Rollback limits are documented (§8 a–e).
- **Export and purge of item-less claims and the new tables:** claims are exported directly `by_user`, their children through the claims parent, and every new table through a userId-prefixed index. Holds. `transactions` is missing from §8's written purge order, but rev 3's reflective test (R3-4) catches it.
- **httpAction auth:** bearer JWT through `ctx.auth`, a tombstone check, the token in a header (no CSRF, never in a URL). Holds.
- **Size before buffering:** Content-Length is refused before the body is read, the stream is capped, and chunked requests without a length are refused. Holds (DA-A-28(f) covers quota charging).
- **Type sniffing:** magic bytes, `nosniff`, `attachment` and the sniffed type. Holds (DA-A-28(b) covers the frontend side).
- **Range requests:** not needed, since downloads are fetched into a blob; ignoring a Range header and returning a full 200 is correct. Holds.
- **Orphan sweep vs a slow registration:** a 24-hour age floor against a request that lasts seconds. Holds.
- **Deletion during an upload:** `finalizeUpload` re-checks the tombstone and deletes only the blob this request stored. Holds.
- **Examples causing real mail or filing:** approval refuses examples on both channels. Holds.
- **`balance()` widening (HC-3/KM2):** an exhaustive switch in the same commit. Holds.
- **Mixed currencies:** per-currency totals, no conversion. Holds, except DA-A-13 and DA-A-19.
- **Negative or unsafe amounts:** `assertMoney` plus the rev-3 cap. Holds.
- **A debit card routed to the credit-card evaluator:** R03 #3 returns `unsupported`. Holds.
- **"Submitted" asserted without evidence:** a user-recorded submission is shown as "You recorded submitting it…", never as sent. Holds, subject to DA-A-9 and DA-A-10.
- **Legacy note-only `packet` counted as asked:** labelled with the `user_reported` sub-figure. Holds.
- **A duplicate concurrent submission record:** the packet status gate plus OCC. Holds.
