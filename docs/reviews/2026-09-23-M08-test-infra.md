## 2. Rule-fixture loader (`convex/testing/ruleFixtures.loader.ts`)

**API.**
- `loadRuleFixtureFile("R02")` returns a `RuleFixtureFile`.
- `loadAllRuleFixtures()` loads every file registered in the manifest.
- `parseRuleFixtureDocument(json, …)` is the pure resolver.
- `missingRequiredCategories(file)`, `missingFactsWithValues(file)`, `moneyWithoutCurrency(file)` report data gaps.
- `CONTRACT_OUTCOMES` and `FIXTURE_OUTCOME_ALIASES` are exported.

Each runnable fixture has this shape:

```
{ id, caseId, variantId, title, categories, path, clock, now, source, action,
  facts, context, expected, expectedAsWritten, annotations, justification }
```

It is deep-frozen. `now` is `Date.parse(clock)`; inject it and never read the wall clock (D138).

**Guarantees.** Each is enforced by throwing a `RuleFixtureError` that names the file and the case.
- **Provenance.** The SHA-256 of the file's bytes must equal `manifest.json` `fixtures[<path>]`. Exactly one manifest pack must point at the file, and it must agree on `ruleId`, version, `scenarioId` and spec. A mismatch throws "fixture drift" and prints both hashes. A `.json` file in the fixtures directory that the manifest does not register also throws.
- **Shape.** Keys are strict: case, variant and top-level keys follow the README "Canonical schema" table, so a typo like `facts_overide` throws instead of silently dropping an override.
  - Facts are `{type, value, state}` with the README's 11 types and 7 states. A non-null value must match its type.
  - A `conflicting` fact needs `candidates`.
  - `amount_minor` must be an integer everywhere, and any currency next to it must be ISO-4217.
  - Clocks are ISO-8601 with an offset.
  - `source` is either `{last_verified_on, refresh_window_days}` or `{record: "missing"}`.
- **Resolution**, per the README and each file's `conventions.loader`:
  - `facts_from` + `facts_override`: chains resolve; cycles and dangling references throw.
  - A variant's `change` and `context_change` apply to that variant only.
  - A variant's `clock` and `source` win over the case's.
  - `action` defaults to `"evaluate"`.
  - A case with a top-level `expected` is runnable, and so is every variant. Each variant must carry its own `expected`: nothing is inherited, and nothing is ever computed.
- **Vocabulary.** Outcomes are mapped through the README alias table: `likely_eligible_missing_evidence` becomes `likely_eligible`, and `not_yet_due` maps 1:1 (contract rev 5.2).
  - The contract list is read from `convex/schema.ts` `evaluationOutcome.members`, so it cannot drift from code.
  - An unknown name throws.
  - The verbatim block is kept in `expectedAsWritten`.
- **Not deployed.** The file name has two dots. The Convex bundler skips any file whose name has more than one dot (`node_modules/convex/dist/cjs/bundler/index.js:370-372`), so this Node-only module (`node:fs`, `node:crypto`) never reaches a deployment. **Warning for everyone:** a single-dot `.ts` file under `convex/testing/` WOULD be bundled, and would also collide with the existing `convex/testing.ts` module in `api`.

**Tests** (`ruleFixtures.loader.test.ts`, 85 at `ad04fe5`):
- **Every registered file.** Scenarios are read from the manifest, so a new file is covered automatically. For each file:
  - hash and manifest agreement;
  - at least 12 cases;
  - every §17 category group present;
  - unique ids;
  - offset clocks;
  - contract outcomes only;
  - deep-frozen output.
- **A data-independent property check.** The loader's output must equal a direct reading of the raw JSON under the documented rules: facts, clock, source, context, action, the verbatim expected block, and the mapped outcomes. It never pins a fixture value, so the rules researcher's revisions do not break it.
- **Synthetic documents** cover resolution, `context_change`/`action`/`tier`/missing-source handling, multi-path outcomes, `not_yet_due`, and 23 failure modes.
- **Drift.** Tampering with the manifest hash, flipping one byte of a file, an unregistered file, a missing pack, or a pack with the wrong version or ruleId each throws.
- **README sync.**
  - Every alias row matches the table in the README.
  - The README's fact states are all accepted.
  - A README row reading "none yet" is tolerated only for an outcome the schema already has and the loader maps 1:1. That covered the gap between `ad04fe5` and M2E; M2E has since mapped `not_yet_due` → `not_yet_due` in the README, and the test passes both before and after.

**Counts at the time of writing.** Before M2D: R01 had 13 cases + 24 variants = 31 runnable fixtures; R02–R05 had 48 cases + 22 variants = 65. M2D then revised every file and added `R01v2.json`, so the counts moved on. The tests use minimums and property checks, not exact counts.

**Findings the loader surfaced. All were fixed by the rules researcher in M2D, and the ratchets are now empty.**
1. R02-05 `delay_cause_controllable` had `{value: "unknown", state: "missing"}`, but the conventions require a missing fact's value to be null.
2. R04-04 `expected.amount.excluded[0]` had an `amount_minor` with no currency.
3. R01.json had no case tagged `missing_fact` or `contradictory_fact`, which contract §9's activation gate requires. M2D added R01-14 and R01-15.

The M09 reviewer confirmed 1 and 2 and listed them as required edits.

**Process note (main went red twice).** `72fe1a2` (R01.json) and `880ec8e` (M2D R02) introduced shapes the README did not yet document, and the loader test failed on `main`. Both times the fix was in the loader. The researcher then wrote the README "Canonical schema" table. The agreed protocol: **before committing a fixture change, run `npx vitest run convex/testing/ruleFixtures.loader.test.ts` (under 1 s); new interpreted keys get a README line and a loader change in the same window.**

## 3. Two-user and clock helpers, and the D138 lint

**`convex/test.setup.ts` (additive; the signatures of `setup` and `signedIn` are unchanged):**
- `twoUsers(t, names = ["Owner", "Other"])` returns `{ owner, other }`, each `{ userId, as }` exactly as `signedIn` returns them.
- `pinClock(at)` fakes **only** `Date` (`vi.useFakeTimers({ toFake: ["Date"] })` + `vi.setSystemTime(at)`) and returns a restore function. `pinClockEach(at)` does the same per test for a `describe` block or a file.
  - Why only `Date`: fully faked timers starve convex-test's nested `ctx.runQuery` inside `t.run`.
  - Scheduler tests keep calling `vi.useFakeTimers()` themselves.
  - The pinned clock is frozen until moved.
  - `_creationTime` follows the fake clock but stays monotonic, so moving the clock backward after an insert is clamped (QA-15).
- `convex/testing/setupHelpers.test.ts` covers these helpers, including the D138 mechanism: a fixed `now` passes `api.budget.status` only while the clock is pinned.

**`convex/testing/clockPins.test.ts`, the lint-style guard.** It parses every collected test file with the TypeScript compiler API.

- **What it flags:** any `query`, `mutation`, `action`, `runQuery`, `runMutation` or `runAction` call on `api.*` (public functions only) that passes a **fixed** `now` with no clock pin in scope.
- **What counts as fixed:**
  - `Date.UTC(…)`;
  - `Date.parse("literal")`;
  - `new Date(<literal>).getTime()`, `.valueOf()` or unary `+`;
  - an epoch literal ≥ 1e12;
  - `+`/`-` arithmetic on any of these;
  - a `const`/`let`/`var` initialised to one of these, resolved through the nearest enclosing declaration. So `{ now: NOW }` and the `{ now }` shorthand both count.
- **What counts as a pin:** `vi.setSystemTime`, `pinClock`, `pinClockEach`, or `vi.useFakeTimers({ now })`. It must be in the same test, in the file, or in an enclosing `describe` or its hooks. A pin in a **sibling** test does not count.
- **Escape hatch:** put `// clock-lint: allow <reason>` on the call line or the line above it. Use it for a fixed time that is valid on any date.

Evidence:
- Today: **0 findings** across all collected test files, so no false positives.
- Not vacuous: stripping the pins from `tracking`, `watches`, `budget`, `dashboard` and `offers` makes each of them flagged.
- Fail-before: on the pre-fix `convex/tracking.test.ts` (`git show f128bf4^:…`) it flags exactly the two D138 calls, at lines 317 and 401.
- Limit: a fixed instant that comes from data, e.g. `Date.parse(fixture.at)`, is invisible to a static check. The clock-shift job (§5) catches that shape.

**Concurrency decision.** The group is keyed on `github.ref` for pull requests and on `github.sha` for pushes. `cancel-in-progress` is set only for pull requests.
- A newer push to a PR still cancels the superseded run.
- Pushes to main never cancel each other, whether in progress or pending. `cancel-in-progress: false` alone would not have been enough: GitHub also cancels a *pending* run when a newer run queues in the same group.
- **A `paths` filter for docs-only pushes was rejected.** The suite reads `docs/rules/**` (fixture JSON, `manifest.json` and `README.md`, through the loader test). On this very day a "docs-only" commit (`72fe1a2`) turned main red, so skipping docs pushes would have hidden a real break. The cost is one full run per push.
- **Observed on GitHub.** Shortly before the change, five consecutive runs on main were `cancelled` (35778474072 through 35778733378). Every run since `54c1ee9` has either completed or run in parallel with others; none has been cancelled.

**e2e wiring (QA-9).**

## 5. Clock-shift job (`npm run test:clockshift`, CI job `clockshift (+400 days)`)

`convex/testing/clockShift.setup.ts` is the M04 sweep shim, now committed.
- `vitest.config.mts` loads it only when `RECOUP_CLOCK_SHIFT_DAYS` is set.
- It moves the JavaScript clock N days ahead while time keeps running. `Date.now` is patched on the underlying `Date`, so vitest's `resetDate` keeps the shift, and `globalThis.Date` becomes a subclass so `new Date()` shifts too.
- Before each test that runs on the real clock, it asserts that the shift is live.
- `npm run test:clockshift` runs the suite at +400 days through the same count gate, which prints "clock shifted +400 days".

**Timing** (clean worktree at `54c1ee9`): `test:ci` took 44.9 s and `test:clockshift` took 45.2 s. The ratio is **1.01×**, under the 2× bar, so the job was added. It runs in parallel with `checks`. On GitHub the whole job, including `npm ci`, took 2 min 30 s (run 35779307160); `checks` took 3 min 16 s.

**Teeth.** A scratch test that takes a fixed instant from data (`Date.parse(fixture.at)`, 2026-09-23T06:00Z) passes the normal run and the clock-pin lint. It fails under `test:clockshift` with "now must be close to the current time".

**Limits.** Only the JavaScript clock in vitest workers moves, not the OS clock. `performance.now()` and timers are not shifted.
