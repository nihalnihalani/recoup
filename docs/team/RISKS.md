- KS3 · **Parser RCE → session forgery (P5, D203).** A code-execution bug in pdf.js running inside the Node action process could read `JWT_PRIVATE_KEY` and mint a session for any user. Mitigations now: synthetic-only extraction, live extraction flag off (D145), exact pin. Preconditions before the flag: CI advisory gate, 7-day patch rule, security re-review. Residual: the Node runtime shares the deployment's environment; isolating the parser (separate deployment or sandbox without auth secrets) is the stronger fix and is not scheduled.
- KX2 · **Transient Convex management-API 401 during e2e teardown** (LOW, D202): best-effort `resetUser` can leave a disposable `@example.com` user; cleaned manually; watch for recurrence.
- KC1 · **CI does not run the browser suite** (MEDIUM, D237): the e2e job reports success but skips Playwright because `E2E_CONVEX_URL`/`E2E_DEPLOY_KEY` are not configured as GitHub secrets. Browser evidence is local QA runs against the dev deployment. Needs the user to add the secrets (agents never handle secret values); until then QA makes the job report "skipped" visibly.
- KX3 · **convex-test timer race** (LOW, D233): a convex-test file that fakes only Date while code under test schedules work can join the scheduled mutation's write layer and fail intermittently ("Write outside of transaction"); fixed for evidence.attach; QA adds a repo-wide guard in M25.
- KX1b · **Convex account above Free-plan limits** (MEDIUM, D224): the CLI reports "Your projects are above the Free plan limits"; deployments may be throttled or paused. A plan change is the user's decision; agents keep dev usage to what verification needs.
- KP1 · **R01 price observations now read transaction facts** (LOW, M20): each R01 observation also reads the transaction's live fact rows once (≤ 1,000) for adapter packs; small for legacy purchases; watch at scale.
- KP2 · **recovery.summary near the read limit** (MEDIUM, D259): 3,004 index ranges / 3,400 docs at the scan caps against a 4,096 limit, mostly per-anchor paid-total reads. Any new per-node/per-anchor read needs a budget test at the caps; a summary read model is the escape hatch.
- KR1 · **Held refunds have no expiry** (LOW, final audit of the retention batch): a needs_review row holding a refund awaiting confirmation keeps `pendingRefund` and `from` until confirmed (disclosed on the Privacy page), and `needsAttention` shows only the newest 50 rows, so an old held refund can drop off the list while still kept. Candidate fix: an expiry that clears the held refund after a documented window, or paging beyond 50.
- KM2 · **ShopSavvy plan size unverified** (LOW, D266): the monthly cap assumes a 1,000-credit plan and calendar-month resets (both from an old comment, D83); 18 credits per lookup (15 inclusive history dates) → 55 lookups/month. Verify against the live account before relying on it.
