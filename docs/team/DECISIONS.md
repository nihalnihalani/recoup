## Decisions from the Phase 0 devil's-advocate review (findings F1–F15)

- D13 · F1 · **Send state machine.** New claim status `queued`. `drafts.approveAndSend` enqueues via the component and sets claim `queued` (never `sent`). A scheduled internal mutation `drafts.reconcileSend` (30s, 60s, 120s, 300s, 600s backoff) reads `agentmail.status(outboundId)`: `agentmailMessageId` non-null → claim `sent`, `threadId` captured, reminder scheduled; `failed|bounced|rejected` → draft gets `sendError`, claim returns to `drafted`, no reminder; still pending after 5 tries → claim `queued` with `sendUnknown: true` and UI says "delivery unknown". Board `asked` counts only `sent|packet|promised`. UI pill for `queued` is "Sending…". · affects T05 schema, T10, T11, C12.
- D14 · F2 · **Inbound processing status.** `processedEvents` gains `userId?`, `status` (`received|processing|succeeded|failed|needs_review`), `kind` (`order|refund|reply|other|paste`), `attempts`, `lastError?`, `summary?`, and a `payload` object holding the minimal fields needed to retry (`inboxId, messageId, threadId, subject, text, from`). `inbound.onMessageReceived` inserts `received` and schedules `intake.processEvent(processedEventId)`, which sets `processing`, runs extraction/classification, then `succeeded` or `failed` (+`lastError`, +`attempts`). Public `intake.retryEvent` re-runs a `failed` row the caller owns. Unmatched refund, `other`, and duplicate orders end as `needs_review` with a human `summary`. Board shows a "Needs attention" list from `processedEvents` where status ∈ {failed, needs_review}. Paste creates a `processedEvents` row with `externalId = "paste:" + sha256(text)` so pasted duplicates dedupe. · affects T03, T07, T11, C05, C06.
- D15 · F3 · **Credit attribution.** A refund credit is matched to an item only when (a) `itemName` matches exactly one item by case-insensitive inclusion, or (b) no `itemName` and exactly one *returned* item has `unitCents×qty === cents`. Otherwise the event goes to `needs_review` with summary "Credit of X could not be matched". A refund email never sets `items.returned`; only the user does. Claims are opened only for items the user marked returned. · affects T07, C09.
- D16 · F4 · **Price check acceptance.** A claim opens only when the extracted price has `currency === purchase.currency`, `confidence ≥ 0.7`, and a single numeric price. Ranges, "from", multi-variant ambiguity, missing currency → `priceChecks` row with `note` and `observedCents` undefined; no claim. `Price` schema gains `isRange: boolean` and `variantMatch: "exact"|"unsure"|"none"`. · affects T06, T09, C08.
- D17 · F5 · **Policy snapshots.** `policies` rows are immutable snapshots: refresh inserts a new row; `purchases.get` returns the latest per kind; claims keep their `policyId`. Passage is stored only if found verbatim in the scraped markdown after whitespace normalization, with `passageStart` offset; otherwise `confidence = 0`, `passage = ""`, `note = "passage not found verbatim"`. Card copy: "Current policy · retrieved <time>". `confirmedByUser` is per snapshot. · affects T03, T08, T11, C07.
- D18 · F6 · **Recipient gate.** `drafts.generate` prefills `to` only from a policy snapshot with `confirmedByUser === true`; otherwise `to` is empty. `drafts.approveAndSend` requires `recipientConfirmed: true` in args unless `to` equals a user-confirmed policy contact for the purchase's merchant. UI shows a checkbox "I confirm this recipient" and a warning when the recipient domain differs from `merchantDomain`. · affects T10, T11, C11.
- D19 · F7 · **Related-ID ownership.** `claims.open` verifies `policyId.userId === userId && policy.merchantDomain === purchase.merchantDomain` and `openedFromPriceCheckId.itemId === itemId`. `drafts.sendStatus` resolves the draft via index `drafts.by_outbound` and checks ownership. `purchases.confirm` checks `item.purchaseId === purchaseId`. · affects T04, T05, T10, C10.
- D20 · F8 · **Money boundaries.** `convex/lib/money.ts` exports `assertCents(n)` (Number.isSafeInteger && n ≥ 0), `assertQty(n)` (safe integer ≥ 1), `assertCurrency(s)` (`/^[A-Z]{3}$/` and `Intl.NumberFormat` does not throw). Public `claims.open` accepts only `{ itemId, feeCents? }` for `return_credit` and derives `expectedCents = unit×qty − fee` server-side; price claims are opened only by `priceWatch.recordCheck`. `toCents` rejects non-finite input. · affects T03, T04, T05, T06.
- D21 · F9 · **Reply amounts.** `replies.promisedCents` is nullable; a `promised_credit` ledger event is written only when the reply states an amount. `balance.promised` is the **latest** stated promise, not a sum. Claim status still becomes `promised` on a `promise|credit_issued` reply. `replies.senderMismatch: boolean` when the sender domain ≠ the draft recipient domain; UI warns. · affects T05 ledger, T10, C13.
- D22 · F10 · **Intake dedupe.** An extracted order whose `(userId, merchantDomain, orderRef)` already exists → `needs_review` "Duplicate of purchase …", no insert. Index `purchases.by_user_domain_order`. · affects T03, T07.
- D23 · F11 · **Reply routing.** Order of routing: (1) `in_reply_to`/`references` matches a draft's `agentmailMessageId` (index `drafts.by_message`); (2) `thread_id` matches `claims.by_thread`; (3) subject token. Tokens are globally unique: `openClaim` loops `newToken()` until no `by_token` hit. · affects T03, T05, T07, T10.
- D24 · F12 · **Ledger hygiene.** New table `claimNotes` (`claimId, userId, kind: note|status|expected_change, text, oldCents?, newCents?`). `adjustExpected` and `markPacketSent` write notes, never ledger events. `confirmCredit` and `recordLaterDebit` take a required client `idempotencyKey`; UI generates one per form submission. Over-credit is shown as "over-credited by X" (unresolved negative, not clamped); board `owed` sums `max(0, unresolved)`. Cross-claim allocation is out of scope: one credit confirms one claim. · affects T03, T05, T11.
- D25 · F13 · **Intake review is mandatory.** Every extracted purchase starts `needs_review`; `purchases.confirm` moves it to `active` and triggers policy fetch. `purchases.purchasedAt` becomes optional; `confirm` requires it; price eligibility and countdowns skip purchases without it. · affects T03, T04, T07, T09, T11.
- D26 · F14 · **Follow-ups.** `followUps.scheduledFnId` is optional: insert → `runAt` → patch. Reminder delay = `max(7 days, policy.windowDays days)` from the relevant returns policy when present. · affects T03, T05, T10.
- D27 · F15 · **Examples.** `isExample` on `purchases`, `claims`, `policies`. `examples.load` is idempotent per user. `priceWatch.eligibleItems` skips example purchases. Board totals exclude example money; example rows carry an "example" pill. · affects T03, T04, T09, T12.

## Reconciliation of planner and devil's-advocate reviews

- D28 · **followUps** (supersedes the optional-field part of D26): `scheduledFnId` stays required. Pattern is schedule-first: `runAt(fireAt, internal.followUps.fire, { claimId })` then insert the row with the returned id. `fire` takes `claimId`, marks pending rows `fired`, and acts only on claim **status** (skips `confirmed|dismissed`), not on `version`, because `applyEvent` bumps version on every partial credit and would silently kill reminders. Reminder delay rule from D26 stands.
- D29 · **sendStatus by draftId.** `drafts.sendStatus({ draftId })` resolves the owned draft, then `agentmail.status(ctx, draft.outboundId)`. `drafts.outboundId` is `v.optional(vOutboundId)` imported from `@agentmail/convex`; no `as any`. D13's reconcile job is named `drafts.reconcileSend` and does what the planner's `captureThread` does plus the failed→`drafted` transition.
- D30 · **Zod for OpenAI strict mode.** No `.max()` on strings (emits `maxLength`, rejected by strict JSON schema); use `.describe("at most N characters")` and slice in code. Zod schemas live in `convex/lib/schemas.ts` (no SDK import) so mutations can parse without bundling `openai`; `convex/lib/ai.ts` holds the client and `extract()`.
- D31 · **Test harness.** `convex/test.setup.ts` registers `agentmail` via `t.registerComponent("agentmail", agentmail.schema, agentmail.modules)` plus both nested workpools `agentmail/sendPool` and `agentmail/callbackPool` via `@convex-dev/workpool/test` (add to devDependencies), sets `AGENTMAIL_API_KEY`, `AGENTMAIL_WEBHOOK_SECRET`, `FIRECRAWL_API_KEY` test values in `process.env`, and starts with `/// <reference types="vite/client" />`. convex-test runs `runAfter(0, …)` on real timers in the background; tests that schedule actions use `vi.useFakeTimers()` before `setup()` and flush with `t.finishAllScheduledFunctions(vi.runAllTimers)` only when needed.

- D33 · **processedEvents final shape.** `{ externalId, kind: "agentmail.message.received"|"paste", status: received|processing|succeeded|failed|needs_review, attempts, lastError?, userId?, claimId?, route?: reply|intake|ignored, summary?, payload?: any }` with indexes `by_external`, `by_status`, `by_user_status`. `onMessageReceived` never throws; unknown inbox → `route: ignored`, `succeeded`.

## Phase 1 checkpoint decisions (adversarial recheck of T04/T05 code, findings R1–R12)

- D38 · R1 · **Idempotency keys are scoped per claim.** Index `ledgerEvents.by_claim_key ["claimId","idempotencyKey"]` replaces `by_key`. Empty key rejected. If the stored event with that key has different `kind` or `cents` → `ConvexError("idempotency conflict")`, never a silent no-op. Asserts run before the dedupe lookup.
- D39 · R2 · **Board `confirmed` is net recovered:** Σ `clamp(confirmed − debited, 0, expected)` per non-dismissed real claim.
- D40 · R3 · **A later debit cannot exceed net confirmed credit** (`cents ≤ confirmed − debited`).
- D41 · R4 · **`adjustExpected` re-derives status** through a shared `deriveStatus(current, balance)` (settled → `confirmed`; `confirmed` but not settled → `reopened`; else unchanged) and refuses `dismissed`.
- D42 · R5 · **`followUps.fire` acts only on pending rows with `fireAt ≤ now`;** no matching row → no-op, claim untouched.
- D43 · R6 · **Non-money boundaries:** `assertTimestamp` (finite, ≥ 0, ≤ now + 1 day), `assertWindowDays` (safe int 0..3650), non-empty `merchantDomain` and non-empty `items` on create/confirm; `policies.confirm` validates `windowDays`.
- D44 · R7 · **One `return_credit` claim per item** unless the previous one is `dismissed`.
- D45 · R8 · **Passage edits clear evidence:** `policies.confirm` with a changed `passage` or `sourceUrl` sets `passageStart` undefined, `confidence: 0`, `userEdited: true` (new optional schema field). `verifyPassage` requires ≥ 40 normalized characters.
- D46 · R9 · **`openClaim` re-checks relationships:** `item.purchaseId === purchaseId`, `item.userId === userId`, `priceCheck.userId === userId`.
- D47 · R10 · **`purchases.remove` archives** (`status: "archived"`) instead of deleting; board and get skip archived; ledger history is preserved. Example `remove` also archives.
- D48 · R11/R12 · Ledger events use `assertPositiveCents`; board skips claims with `isExample` even on real purchases; `dismiss` refuses `confirmed`.
- D49 · **T10 guard:** `reconcileSend` must not overwrite `confirmed`/`dismissed` (a claim can be confirmed while `queued`); it only transitions from `queued`.
- Drift noted, accepted: `processedEvents.kind` stays `v.string()` (tests use free-form kinds).
- D50 · **Generated API is committed with its module.** Whoever adds or renames a Convex module runs `npx convex codegen` and includes `convex/_generated/api.d.ts` in the same commit. Regenerating is not hand-editing. Found because HEAD failed typecheck in an isolated worktree while every lane's local tree passed.
- D51 · **Component test module maps are globbed by us, exhaustively.** Vite's `import.meta.glob` ignores `**/node_modules/**` unless `{ exhaustive: true }`, so the `modules` exported by `@agentmail/convex/test` and `@convex-dev/workpool/test` are empty when evaluated from `node_modules`. `convex/test.setup.ts` globs each component's `src/component/**/*.ts` itself with `exhaustive: true` and calls `t.registerComponent` directly. `@firecrawl/firecrawl-convex/test` has the same latent defect; apply the same treatment if a test ever dispatches into it. Supersedes D37.

## Checkpoint 2 decisions (send/webhook/intake review, findings S1–S12)

- D52 · S1 · `drafts.markPacketSent` refuses claims in `confirmed|dismissed|queued|sent|packet`.
- D53 · S2 · `replies.apply` always records the reply row; it writes a ledger event only when the claim is not `dismissed`/`confirmed`... correction: not `dismissed` (a confirmed claim may still receive a stated promise, recorded as promised_credit without status change per D49 semantics). A reply on a dismissed claim never fails the event.
- D54 · S3/S5 · **Intake keys are external and per user.** Paste: `paste:${userId}:${sha256}`. Refund credits: idempotency key `${messageIdOrPasteHash}:${itemId}:${creditIndex}`; a key conflict on one credit marks that credit `needs_review` in the summary and does not fail the event.
- D55 · S4 · Refund purchase matching considers only `status === "active"` purchases that are not `isExample` (unless the refund's merchant explicitly contains "(example)"), prefers exact `orderRef`, then exact merchant name, then inclusion; `openClaim` from intake passes `purchase.isExample`.
- D56 · S6 · `approveAndSend` resets `sendUnknown`; `reconcileSend` failure path clears it. Public owner-gated `drafts.recheckSend({ draftId })` runs one more reconcile on demand.
- D57 · S7 · `claims.dismiss` on a `queued` claim attempts `agentmail.cancel(outboundId)` best-effort (wrapped), records a note either way.
- D58 · S8/S9/S10/S11/S12 · Subject normalization strips any `[RC-…]` before appending the claim token. Intake validates `unitPrice`/`purchasedAt`/credit amounts at the boundary and routes violations to `needs_review`, never `failed`. `lastError` stored raw server-side; `board.attention` exposes a sanitized `errorSummary` ("Extraction failed", "Provider error", "Invalid data") only. **D11 amended:** the submitted `{to, subject, body}` are the approval and are stored on the draft in the same transaction as the enqueue; additionally `approveAndSend` requires the draft to be the newest draft on the claim ("a newer draft exists" otherwise). `REOPEN_ELIGIBLE` gate in replies removed; status derivation goes through `statusAfterEvent`/`deriveStatus` only.
